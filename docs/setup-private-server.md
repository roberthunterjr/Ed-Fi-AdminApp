# Configuration to set up the environment on a private server

This guide describes how to run the Ed-Fi Admin App environment on Ubuntu Linux when it is accessed through a public IP address. It is based on the current changes in `compose/.env.example`, `compose/adminapp-services.yml`, `compose/ssl/generate-certificate.sh`, `compose/settings/populate-oidc.ps1`, and `packages/api/config/production.js-edfi`.

## Modified Files

The following files contain the changes required for this setup:

- `compose/.env.example`: Uses the public IP for the base URL, Keycloak hostname, frontend API URL, and identity-provider account URL.
- `compose/adminapp-services.yml`: Publishes the Keycloak and PostgreSQL ports for environments that require external access.
- `compose/settings/populate-oidc.ps1`: Uses the public IP as the default OIDC issuer.
- `compose/ssl/generate-certificate.sh`: Adds the public IP to the certificate's `subjectAltName` when generating HTTPS certificates.
- `packages/api/config/production.js-edfi`: Uses the public IP for the frontend, API, and OIDC issuer URLs.

## Considerations

- Set `PUBLIC_IP` to the server's actual public IP address before running the commands in this guide.
- The IP address must point to the Ubuntu server, and the published ports must be allowed both in the provider's firewall and in `ufw`.
- The certificate generated by this procedure is self-signed. Browsers will display a warning until the certificate is installed or a certificate issued by a certificate authority is used.
- `production.js-edfi` and the Compose files contain example values, including `big-secret-123`. Change the secrets before using the environment outside a test network.

## 1. Prepare Ubuntu

Install Docker Engine and the Docker Compose plugin. Then verify that the user can run Docker:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git openssl
docker --version
docker compose version
```

Add the current user to the `docker` group if the user is not already a member:

```bash
sudo usermod -aG docker "$USER"
```

Log out and log back in for the group change to take effect.

## 2. Download and Configure the Project

```bash
git clone <REPOSITORY_URL>
cd Ed-Fi-AdminApp
cp compose/.env.example compose/.env
chmod +x compose/ssl/generate-certificate.sh
```

Set the public IP in a shell variable and update `compose/.env`:

```bash
export PUBLIC_IP="<PUBLIC_IP>"
sed -i "s/<PUBLIC_IP>/$PUBLIC_IP/g" compose/.env
```

Verify that the following variables use `https://${PUBLIC_IP}`:

```dotenv
BASE_URL=https://${PUBLIC_IP}
ALLOWED_ORIGINS=https://${PUBLIC_IP}
KEYCLOAK_HOSTNAME=${PUBLIC_IP}
VITE_API_URL=https://${PUBLIC_IP}/adminapp-api
VITE_IDP_ACCOUNT_URL=https://${PUBLIC_IP}/auth/realms/edfi/account/
```

Also review the passwords, OIDC client secrets, and any installation-specific values in `compose/.env`.

## 3. Configure the HTTPS Certificate

Generate the certificate with the public IP included as a `subjectAltName`:

```bash
cd compose/ssl
chmod +x generate-certificate.sh
./generate-certificate.sh "$PUBLIC_IP"
```

The script also accepts the `PUBLIC_IP` variable without passing it as an argument:

```bash
PUBLIC_IP="$PUBLIC_IP" ./compose/ssl/generate-certificate.sh
```

The expected result is the creation or update of `compose/ssl/server.crt`, `compose/ssl/server.key`, and `compose/ssl/dhparam.pem`.

## 4. Configure the Application URLs

Edit `packages/api/config/production.js-edfi` and replace the public host with the value of `PUBLIC_IP`. At a minimum, these URLs must match:

```javascript
FE_URL: 'https://<PUBLIC_IP>/adminapp'
MY_URL: 'https://<PUBLIC_IP>/adminapp-api'
SAMPLE_OIDC_CONFIG.issuer: 'https://<PUBLIC_IP>/auth/realms/edfi'
AUTH0_CONFIG_SECRET_VALUE.ISSUER: 'https://<PUBLIC_IP>/auth/realms/edfi'
```

If the frontend image is built using the variables in `compose/.env`, rebuild it after changing `VITE_API_URL` or `VITE_IDP_ACCOUNT_URL`.

## 5. Allow the Required Traffic

For normal access to the environment, expose only HTTPS:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 443/tcp
sudo ufw enable
sudo ufw status verbose
```

The current changes in `compose/adminapp-services.yml` allow Keycloak and PostgreSQL to listen on all interfaces when their ports are published. If remote access to these services is required, allow it only from a trusted administrative network, not from the entire Internet:

```bash
sudo ufw allow from <ADMINISTRATION_IP> to any port 8080 proto tcp
sudo ufw allow from <ADMINISTRATION_IP> to any port 5432 proto tcp
```

If remote access is not required, keep these ports blocked in the firewall and consider binding them back to `127.0.0.1` in `compose/adminapp-services.yml`.

## 6. Start the Services

From the repository root, run the official startup script:

```bash
pwsh ./compose/start-services.ps1
```

Check the status and logs:

```bash
docker ps -a

docker logs -f edfiadminapp-api 
docker logs -f nginx

```

## 7. Automatic OIDC Configuration

The OIDC configuration is registered automatically as part of the startup process. It is not necessary to run `compose/settings/populate-oidc.ps1` manually.

Verify that the issuer configured in the database, Keycloak, and `production.js-edfi` is exactly the same, including `https`, the IP address, and the `/auth/realms/edfi` path.

## 8. Validate Access

From the server:

```bash
curl -kI "https://${PUBLIC_IP}/adminapp/"
curl -kI "https://${PUBLIC_IP}/auth/realms/edfi/.well-known/openid-configuration"
```

From an external computer, open:

```text
https://<PUBLIC_IP>/adminapp/
```

Confirm that the browser loads the frontend, redirects to Keycloak, and returns to the application without `issuer`, CORS, or certificate errors.

## Stop the Environment

```bash
pwsh ./compose/stop.ps1
```

The script stops and removes the containers but preserves the volumes. Do not use commands that remove volumes unless you intend to delete the persisted data.
